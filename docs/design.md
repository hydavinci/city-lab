# 苏州城市实验室

## 已确认的需求

- 范围为江苏省苏州市完整行政区域，不限于古城或金鸡湖。
- 根据真实地图生成三维城市，不生成虚构道路或随机建筑。
- 本机运行、浏览器访问，准备好数据后可离线浏览。
- 参考图的深色控制台、城市夜景和参数控制是视觉方向，不复制重庆的城市形态。
- 初始实现于 2026-10-14 在空目录中开始；发布仓库为 `hydavinci/city-lab`。

## 数据与真实性

数据来自 OpenStreetMap，苏州市边界关系为 `relation/4430941`。
保存原始响应、OSM 快照日期、处理统计、来源和 ODbL 署名。
禁止把缺数据解释为空地，禁止把导入覆盖率解释为现实建筑覆盖率。
高度优先读取 height，其次按 building:levels × 3.2 m 推算，
最后使用固定保守建筑类型默认值；后两种均标记估算。
不使用 GCJ-02 底图混配 WGS84 建筑。

## 系统边界

1. Node.js/TypeScript 离线数据管线负责 Overpass 下载、响应完整性检查、
   几何规范化、空间分块与生成清单。
2. React/TypeScript 工作台负责配置、错误提示、地点定位和数据统计。
3. CesiumJS 负责椭球地理底座、相机、批量建筑网格、离线道路水域和夜景材质。
4. Vite 开发服务或预览服务只监听 localhost；无需云令牌。

数据管线与前端共享类型和地理规则，因此采用 TypeScript 而不是原计划中的 Python，
避免两份高度推断和分块规则。首版采用可审计的 GeoJSON 网格分块，
不声称已实现 3D Tiles 编码或照片级实景建模。

## 加载与性能

全市边界和概览地表常驻，建筑按视口选择最近的有限数量网格。
远景隐藏建筑细节，近景加载真实轮廓的拉伸模型。
移出视口销毁网格，取消过期网络请求，限制并发与缓存。
低、中、高画质控制像素比、建筑网格数量和泛光。
30 FPS 是待基准设备验证的目标，不作为未经测量的交付结论。

## 用户可见行为

- 全市总览和多个区域定位点；定位点不定义数据范围。
- 日夜、建筑、水域、道路、绿地、边界与标签控制。
- 建筑点选展示源标识、高度依据、估算标记。
- 配置导出、导入、本地保存，截图导出。
- 数据加载失败、配置损坏、图形初始化失败显示明确提示。
- 全市采集范围与源数据实际完整性分别说明。
- 地形为椭球平面，无高程数据，不展示假山体或假地标。

## 验证

单元测试覆盖高度解析、孔洞、空间网格、数据去重、部分下载拒绝和配置校验。
端到端测试真实启动浏览器，验证离线资源、场景、控制、配置与失败状态。
运行 TypeScript 检查、生产构建、数据一致性检查及本地 HTTP 健康检查。
